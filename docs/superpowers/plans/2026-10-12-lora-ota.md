# C8T6 LoRa OTA Implementation Plan

Goal: implement the user-approved bootloader, two games and PC uploader.
Architecture: fixed B bootloader, fixed A application, internal staging, two-page journal.
Tech stack: STM32F103C8T6, StdPeriph 3.5, ARMCC5, ATK-MWCC68D UART, Python tkinter/pyserial.

## Global Constraints
- Work in this new repository; original source remains at its original path and a provenance-preserving copy under firmware/legacy.
- B 0x08000000 length 0x4000; A 0x08004000 length 0x5C00; stage 0x08009C00 length 0x5C00; metadata pages 0x0800F800 and 0x0800FC00, each 0x400. RAM 0x20000000 length 0x5000.
- OLED PB6/PB7; UART1 PA9/PA10 9600 8N1; active-low PA0 EXTI key. LoRa modules externally configured normal transparent mode.
- Boot waits 3000ms normally; a key or durable request stays in updater. App key persists request, displays prompt, waits for manual reset.
- Do not erase A until stage fully validates and durable INSTALLING record commits. Resume INSTALLING from first page on reboot. No factory rollback.
- No on-board validation claim without actual hardware evidence.

## Task 1: portable OTA core and protocol
Implement common C code with flash read/erase/write callbacks, CRC32, byte-stream protocol, two-page committed journal, request/begin/data/finish/install/cancel/validate API. Native GCC executable tests use real portable code and flash simulator to check faults at writes/erases. Detailed interface in docs/implementation/core-brief.md.

## Task 2: STM32 port and application integration
Build IRQ-driven UART ring, Flash adapter, monotonic time source independent of legacy SysTick delays, debounced PA0 EXTI, guarded app jump assembly, boot event loop and legacy game adapter. App handles only INFO query and rejects upgrade commands without reboot; binary frames stay out of text command stream. Emit visibly different deer and dinosaur sprite/version builds. Independent linker addresses and compile-time VTOR offset.

## Task 3: PC uploader
Provide shared Python wire codec, retries, query/begin/data/commit/cancel, CLI and Tkinter GUI; use session+sequence matching and explicitly distinguish transfer/verification/install completion. Integration-test against native C simulator, not a Python imitation of firmware.

## Task 4: reproducible builds and packaging
Use detected D:/keil5/ARM/ARMCC/bin tools, support configurable toolchain root. Build boot/deer/dinosaur with link-limit failures. Produce BIN/HEX/AXF/MAP and first-flash HEX with correct committed app metadata; independently validate vectors and bounds. Provide Keil projects as well as CLI build.

## Task 5: review, documentation and publication
Review core and uploader plus complete system, address faults, execute fresh tests/builds, document precise test evidence and pending hardware matrix. Write Chinese README, protocol/flash schema, manual installation and module configuration instructions. Commit and push feature branch, then publish completed initial repository content on main without force-push.
