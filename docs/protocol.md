# GBOT 升级协议 v1

所有多字节整数为小端。CRC32/ISO-HDLC与Python `zlib.crc32`一致；字符串 `123456789` 的结果是 `CBF43926`。

## 帧格式

| 偏移 | 长度 | 内容 |
|---|---:|---|
|0|4|ASCII `GBOT`|
|4|1|版本1|
|5|1|消息类型|
|6|4|会话编号|
|10|2|序号|
|12|2|载荷长度0..132|
|14|可变|载荷|
|14+长度|4|前面全部字节的CRC32|

最大帧150字节。按字节流解析，可以拆帧/粘帧；不能把UART空闲中断或LoRa分段视为完整协议帧。MCU部分帧超时2秒后重新同步；UART错误/溢出丢弃受损接收突发，应用将二进制内容与游戏单字节指令隔离。

## 类型和应答

QUERY=1，BEGIN=2，DATA=3，COMMIT=4，CANCEL=5，ACK=6，NACK=7，DONE=8。

- QUERY载荷为空，两种程序都可返回设备信息。
- BEGIN序号0，载荷5个uint32：MCU标识`0x103C8`、应用基址`0x08004000`、BIN长度、BIN CRC、版本。会话编号非零。
- DATA从序号1开始，载荷为uint32偏移加1..128字节。非最后一包必须恰好128字节；最后奇数字节在Flash适配中补FF，但补字节不计入CRC。
- COMMIT使用下一序号，空载荷；校验暂存、持久化安装状态、复制并校验A区、提交新版本有效状态，成功返回DONE。
- CANCEL使用当前期望序号，空载荷，只允许接收阶段取消。
- ACK/NACK/DONE回显请求的会话和序号，载荷固定28字节：错误码、已接收偏移、状态、升级请求标志、当前应用版本、当前应用长度、当前应用CRC（各uint32）。

状态低31位：EMPTY0、VALID1、RECEIVING2、INSTALLING3。状态bit31置位代表运行的是游戏应用，清零代表Bootloader。应用拒绝BEGIN/DATA/COMMIT/CANCEL；按键保存请求后仍需手动复位。

错误码：0成功、1状态不允许、2长度错误、3芯片/地址不匹配、4向量表错误、5CRC错误、6Flash失败、7会话错误、8序号错误、9偏移错误、10重复内容不一致。

重复BEGIN只在同一活动会话及相同固件信息下重新应答，不清空已收内容。只接受最后一包的完全匹配重复DATA；不同内容拒绝。安装结果提交后，同一运行上下文的重复COMMIT再次返回DONE；冷重启后会话消失，可通过QUERY核对已安装版本/长度/CRC。

## 片内状态记录

两页各16条64字节记录。字段：0魔数`0x4F54414D`、4代数、8状态、12请求、16/20/24旧应用长度/CRC/版本、28/32/36候选长度/CRC/版本、40..55保留0、56前56字节CRC、60提交半字`0xA55A`、62保留`0xFFFF`。

先写入并校验前60字节，最后写提交标记。扫描忽略撕裂或CRC不符的记录，采用模32位代数判断新旧。始终保留最新有效记录所在页，轮换擦除另一页；初始合并HEX写入序号1、VALID、请求0及对应游戏描述。
